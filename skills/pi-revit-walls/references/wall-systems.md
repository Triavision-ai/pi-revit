# Wall systems, types, layers and materials

Read this when choosing or changing a wall kind or assembly. These are Autodesk-documented concepts and API routes; the selected PI-Revit tool schema determines which operations have a dedicated tool, and live tests determine which package behaviors are verified.

## Identify the system before creating or editing

`WallType.Kind` distinguishes `Basic`, `Curtain`, `Stacked` and `Unknown`. Do not infer kind from a localized type name or assume that a `Wall` represents a Basic wall. The wall instance supplies `WallType`, `Flipped`, `Orientation`, `CrossSection`, `StructuralUsage`, `CurtainGrid`, and stacked-wall membership where applicable. `Wall.Orientation` is the exterior normal **at the curve's start**; on a curved wall, use local geometry where the position matters. See Autodesk's [wall API guide](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Walls_Floors_Ceilings_Roofs_and_Openings/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Walls_Floors_Ceilings_Roofs_and_Openings_Walls_html.html) and [Wall class](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/b5891733-c602-12df-beab-da414b58d608.htm).

| Kind | Design and inspection decision | API route when no dedicated tool covers the task |
| --- | --- | --- |
| Basic | Choose a loaded type by ID and inspect its compound structure, width, core and materials. Structural usage is an instance choice; type Function can affect default room bounding and structural usage. | `Wall.Create` with a valid curve or profile; `WallType.GetCompoundStructure`; `Wall.StructuralUsage`. |
| Curtain | Treat the wall, curtain grid, panels and mullions as related but distinct objects. A grid/panel result is not proof that the whole assembly matches the intended pattern. | Check selected type and supported creation route; inspect `Wall.CurtainGrid`, then `CurtainGrid.AddGridLine`, `GetPanelIds`, panel type and mullion APIs as needed. |
| Stacked | Inspect the parent and subwalls. Dimensions, type, materials and openings may need member-level checks; do not count parent and members as one undifferentiated wall. | Use `Wall.GetStackedWallMemberIds()` for a consistent stacked wall; inspect members in returned bottom-to-top order. Check type creation limits in the selected build. |
| Unknown | Stop type-specific assumptions and inspect the actual object/bridge result. | Verify class, type kind and supported API members before any write. |

Autodesk documents [curtain grids, panels and mullions](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-ArchDesign/files/GUID-BBC16AF1-88C1-4B2E-A23A-917C3F427E97.htm), the [CurtainGrid API](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/5e0d5b7c-aaa1-d299-6fb8-2faa65b1857a.htm), and [stacked-wall member IDs](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/66ec8d4e-25cd-1e14-3b25-d9d3a0f5cce9.htm). These APIs document a route, not a promise that every arrangement is accepted by `Wall.Create` or the current dedicated tool.

## Compound Basic wall assembly

A Basic wall type's `CompoundStructure` orders layers from exterior to interior. Inspect `GetLayers()`, each layer's width, function, priority and material ID, and the first/last core layer indices before selecting a core or finish alignment. `GetOffsetForLocationLine` gives an offset from wall center to a location-line option. A vertically compound structure can change by elevation, so inspect the actual geometry at relevant heights. A layer with an invalid material ID can inherit a category material. [CompoundStructure guide](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Walls_Floors_Ceilings_Roofs_and_Openings/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Walls_Floors_Ceilings_Roofs_and_Openings_CompoundStructure_html.html), [API members](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/dc1a081e-8dab-565f-145d-a429098d353c.htm).

Changing the compound structure on an existing `WallType` changes every instance using that type. For a requested new assembly, discover a suitable source type, duplicate it with `ElementType.Duplicate` under a distinct project-appropriate name, adjust the copy, then apply it with `HostObjAttributes.SetCompoundStructure`. Reassign only the intended walls. Check name collisions and existing-object scope before duplication. `CompoundStructure.SetLayers` resets core/shell, variable layer, structural material and vertical-homogeneity settings; re-establish intended settings instead of assuming they survive. [Compound structure edit guidance](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Walls_Floors_Ceilings_Roofs_and_Openings/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Walls_Floors_Ceilings_Roofs_and_Openings_CompoundStructure_html.html), [SetLayers behavior](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/0392b682-451d-5399-54b5-44373ce941c6.htm).

Materials and thickness come from the model or user design, never a country-wide default. Resolve explicitly assigned materials to current-document IDs and preserve intentional category-derived materials. Verify layer order, core boundaries, width and assignments after the type edit. `Wall.Width` is the overall wall thickness; it is not a per-instance layer editor. [Wall type properties](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-ArchDesign/files/GUID-C6A3DD86-FFAF-4781-8E50-5714965C24BE.htm).

## Wrapping, function, room and structure

Wrapping at ends/inserts is partly a type and compound-structure decision. The type defines which shell layers can wrap; `Wall.GetValidWrappingLocationIndices` and `AllowWrappingAtLocation`/`DisallowWrappingAtLocation` control eligible wall locations. End-join allowance and end wrapping are separate. Tapered walls do not support type wrapping in Autodesk's wall type properties. [Wall wrapping API](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Walls_Floors_Ceilings_Roofs_and_Openings/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Walls_Floors_Ceilings_Roofs_and_Openings_Walls_html.html), [type properties](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-ArchDesign/files/GUID-C6A3DD86-FFAF-4781-8E50-5714965C24BE.htm).

Wall type Function is a classification; it can influence initial `Room Bounding` and structural defaults but does not substitute for checking the created instance. For Basic walls, `StructuralUsage` distinguishes `NonBearing`, `Bearing`, `Shear` and `Combined`. Room bounding affects room/space computation, so verify the intended phase and spatial boundary rather than treating a parameter value alone as proof of a correct room. [Wall API guide](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Walls_Floors_Ceilings_Roofs_and_Openings/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Walls_Floors_Ceilings_Roofs_and_Openings_Walls_html.html), [Rooms API guide](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Discipline_Specific_Functionality/Architecture/Revit_API_Revit_API_Developers_Guide_Discipline_Specific_Functionality_Architecture_Rooms_html.html).
