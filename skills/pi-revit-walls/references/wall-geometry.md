# Wall path, elevation and interactions

Read this when a wall's path, location line, cross section, vertical extent, attachment, join or opening matters. The API routes below are documented by Autodesk; check installed signatures with `search_api_docs` and the selected build before custom execution. A documented API does not mean the current dedicated `create_walls` schema exposes it.

## Path and orientation

Define the design path in a named coordinate frame and explicit length unit. The current `create_walls` contract takes document-internal XY coordinates for path walls and absolute document-internal XYZ vertices for a vertical profile; shared/survey coordinates need an explicit transform. For a line, provide start/end. For a circular arc, provide center, radius and a counterclockwise degree span from +X; for an ellipse, provide center, X/Y radii and the same angle convention. A profile needs 3–100 ordered XYZ vertices in one vertical plane; the tool closes the last edge. The selected schema and [wall manual](../../pi-revit/references/tools/create_walls.md) define validation and shape-specific fields. Autodesk's `Wall.Create` curve overload can still reject a curve or type pairing, so inspect the retained result. [Wall.Create overload](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/0ce4c555-4cee-f5fd-2e84-43cacf34ac5c.htm), [profile overload](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/6c247699-c8e5-91df-67f7-470d10fa7ba3.htm).

The six Autodesk location lines are wall center, core center, exterior/interior finish face, and exterior/interior core face (`WALL_KEY_REF_PARAM`). Choose the intended **plane** and exterior side before drawing. The current dedicated tool aligns those planes on Basic line and arc paths through the type's compound structure; noncenterline placement needs a usable compound structure and is not generally available on Curtain or Stacked types. Ellipse and profile paths require `WallCenterline`. For Basic walls, `flip` reverses orientation; Autodesk states that `Wall.Flip()` does not change `Orientation` for Curtain and Stacked walls. A curved wall's `Orientation` reports the exterior normal only at the start, so compare alignment using the local curve/face at the point of interest. Changing `WALL_KEY_REF_PARAM` alone does not move a physical plane onto a supplied path. [Autodesk wall location-line API](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Walls_Floors_Ceilings_Roofs_and_Openings/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Walls_Floors_Ceilings_Roofs_and_Openings_Walls_html.html), [Wall.Flip](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/4fa072e8-7840-66bc-78a4-e13ef24f0d41.htm), [CompoundStructure offsets](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/dc1a081e-8dab-565f-145d-a429098d353c.htm).

Elliptical walls have additional restrictions: Revit UI guidance requires a wall-center location line and does not permit moving that line after placement. The current tool likewise rejects noncenterline ellipses because offsetting the ellipse produces a curve that Revit will not accept as the wall location curve. Profile editing is unavailable for arc/ellipse walls. [Elliptical-wall practices](https://help.autodesk.com/cloudhelp/2022/ENU/Revit-ArchDesign/files/GUID-77AB37AE-41E1-4F22-A42A-4F795566B629.htm), [wall profile API](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Walls_Floors_Ceilings_Roofs_and_Openings/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Walls_Floors_Ceilings_Roofs_and_Openings_Walls_html.html).

For an existing wall, `LocationCurve.Curve` can move or resize a supported curve-based wall, and `Wall.Flip()` can reverse a Basic wall's orientation. These edits can alter joins, hosted inserts, constraints and room boundaries. Inspect them before and after the edit; use the selected tool's supported edit operation where available and check the installed API before custom execution. [LocationCurve.Curve](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/b03df3be-687a-2ac8-e28d-2e038ecac142.htm), [Wall.Flip](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/4fa072e8-7840-66bc-78a4-e13ef24f0d41.htm).

## Base, top and shape in elevation

For a path wall, choose a base level and optional base offset, then exactly one of unconnected `height` or `top_level_id` with optional `top_offset`. The physical base and top must be computed in the document's internal elevation frame; a level's displayed elevation may use another datum. A level-constrained wall follows its top level when the level moves, while an unconnected wall keeps a height. Profile vertices instead specify absolute XYZ, including elevation; omit height, top and base offsets. Verify actual constraints and geometry after commit. [Wall instance properties](https://help.autodesk.com/cloudhelp/2020/ENU/Revit-Model/files/GUID-ED2045E5-90BF-418F-AAD6-3BB1544F34F5.htm), [PI-Revit wall manual](../../pi-revit/references/tools/create_walls.md).

For slanted or tapered designs, use the dedicated tool's `cross_section` (`Vertical`, `SingleSlanted`, `Tapered`) and applicable degree angle fields when its schema covers the shape. `Wall.IsWallCrossSectionValid` and `Wall.CrossSection` provide a companion API route. Tapered walls require a variable layer in their compound structure; type default face angles can be overridden per wall. A disposable 2025.4 test committed tapered line and arc walls only after a suitable Basic type was duplicated and given a variable layer. Confirm insert orientation and where width is measured when they affect the result. Do not apply a vertical wall's plan offset formula to a slanted/tapered face without inspecting its 3D geometry. [Wall API guide](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Walls_Floors_Ceilings_Roofs_and_Openings/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Walls_Floors_Ceilings_Roofs_and_Openings_Walls_html.html), [tapered walls](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-ArchDesign/files/GUID-F1E354E8-9B44-42C9-A554-818A921F59BD.htm).

For a nonrectangular **elevation profile**, Autodesk provides `Wall.Create` overloads with a planar `IList<Curve>` and, optionally, a normal perpendicular to that profile. For an existing eligible straight wall, check `CanHaveProfileSketch`, use `CreateProfileSketch`, regenerate, and edit within `SketchEditScope`. The API rejects profile sketches for some walls, including non-straight, tapered, infill and certain curtain cases. A profile opening and a wall path curve solve different design problems. [Profile creation overload](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/6c247699-c8e5-91df-67f7-470d10fa7ba3.htm), [CreateProfileSketch limits](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/d582a742-d89d-6edb-90e2-dd16633bd8b8.htm).

An attachment to a roof, floor, ceiling, toposolid or another wall is different from a top-level constraint. Verify the target in the same document and use `Wall.IsValidTargetAttachment`, `AddAttachment`/`RemoveAttachment` and `GetAttachmentIds` only when available in the selected Revit build (`AddAttachment` was introduced in Revit 2025.2). Attaching can alter the effective wall profile; reread dimensions and dependent elements. [Attachment API](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/bef619ea-dede-2795-d767-04a464a997f0.htm), [attachment behavior](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-ArchDesign/files/GUID-ED60CE62-B955-45E9-9D7D-00F1552D858C.htm).

## Joins, wrapping, openings and hosted elements

End joining is a per-end allowance on the wall curve: `WallUtils.AllowWallJoinAtEnd` or `DisallowWallJoinAtEnd` with index 0 or 1. It can cause nearby ends to join and may change neighboring geometry or material takeoff. `JoinGeometryUtils` addresses geometric joining of elements and is not the same as toggling an end join. Reread both sides of a join and inspect plan/section cleanup. End wrapping is separate and depends on the type's compound structure. [WallUtils API](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/e77a6d4e-bfbc-a146-0e29-54276bbb8056.htm), [wall wrapping](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Walls_Floors_Ceilings_Roofs_and_Openings/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Walls_Floors_Ceilings_Roofs_and_Openings_Walls_html.html).

`document.Create.NewOpening(wall, pntStart, pntEnd)` makes a rectangular opening in a straight or arc wall; its points must define valid opposite corners. Nonrectangular holes need a profile or another supported cutting route, not an assumed wall-opening overload. Doors/windows are hosted family instances, and an embedded curtain wall is another distinct relationship. Discover the host, symbol and placement kind, then use the appropriate `NewFamilyInstance` overload or checked API route; the current `place_family_instances` tool covers only unhosted `OneLevelBased` families. Inspect `HostObject.FindInserts` and dependent IDs afterward; Revit may change the host's net geometry and quantities. [Opening API guide](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Walls_Floors_Ceilings_Roofs_and_Openings/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Walls_Floors_Ceilings_Roofs_and_Openings_Opening_html.html), [FindInserts](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/58990230-38cb-3af7-fd25-96ed3215a43d.htm), [family-instance overloads](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/ab1718f9-45fb-b3d3-827e-32ff81cf929c.htm).

## Model context

Check whether the wall is in a group, design option, workset, phase, linked model, or host relation before changing it. Do not apply host-model IDs to linked elements. New elements can inherit a phase from the active view; verify `CreatedPhaseId`/`DemolishedPhaseId` when phase matters and check phase order before editing. A wall's room-bounding flag should be checked in the intended phase and with actual rooms/spaces. [Wall class context](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/b5891733-c602-12df-beab-da414b58d608.htm), [CreatedPhaseId](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-API-MainReference/files/html/c6032e01-f7cb-b2ea-3312-697d14216a31.htm).
